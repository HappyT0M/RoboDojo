# RoboDojo 绳球任务键盘遥操设计

## 目标

新增一个 RoboDojo 图形窗口键盘遥操入口，让操作者在 `put_rope_ball_in_basket` 场景中手动移动 X5 机械臂、开合夹爪，并录下操作过程。首版只支持当前已跑通的绳球入篮任务，不扩展其他任务定义，也不接入 VLA/WAM。

## 入口与环境

- 新增 `scripts/teleop_deformable_task.py`，沿用 `record_deformable_tasks.py` 的配置组装、`create_eval_env`、场景种子和摄像头采集流程。
- 默认任务为 `put_rope_ball_in_basket`，提供 `--task_name`、`--seed`、`--device_id`、`--out_dir` 参数。
- 该入口需要 Isaac Sim 图形窗口，不能以 `--headless` 作为交互遥操方式。启动时通过 Isaac Sim 的键盘事件接口订阅输入，并在退出时注销订阅。
- 复用当前 `arx_x5` 双 X5 配置。通过 `--arm left|right` 指定被遥操的手，另一只手保持 reset 后的末端位姿和夹爪状态。

## 控制方式

- 用键盘按住移动键，对所选末端目标位姿做小步笛卡尔 XYZ 平移；末端旋转保持 reset 时的姿态。
- 通过 RoboDojo 现有 `env.take_action()` 和 IK 流程将目标位姿转换为关节目标，不直接改写机械臂 USD 或关节控制器。
- 单独的开、合夹爪按键控制夹爪状态。启动信息中打印按键映射、步长/速度和退出保存按键。
- 每次循环都推进环境并采集观测；未按移动键时机械臂保持目标位姿，仿真仍继续运行。

## 风力选项

- 默认无风。
- 提供可选的恒定风速向量参数；启用后复用现有 `utils.rigid_wind`，仅对已发现的动态任务刚体施加风力。
- 启动日志和数据记录中写出请求风速、控制手臂、任务名和场景种子。

## 记录结果

- 每次遥操结束时，通过 RoboDojo 现有 `save_video` 机制保存可用摄像机视频。
- 同时保存逐控制步 JSONL，至少记录时间/步号、键盘动作、所选手臂、末端目标位姿、夹爪开合、风速和当前任务。
- 文件写入 `--out_dir/<task_name>/`，文件名带时间戳和风速标记，避免覆盖旧录制。
- 按退出保存键、窗口关闭或异常退出时，尽可能完成视频落盘并释放键盘订阅、环境和 Simulation App 资源。

## 错误处理

- 如果获取不到图形窗口或键盘设备，打印明确提示，说明需要带窗口运行并退出，不回退到伪遥操。
- IK 求解失败时保持上一目标位姿，不发送无效目标，并在终端提示。
- 如果没有发现可施加风力的动态刚体，保留任务运行并报告诊断信息。

## 验收标准

1. 默认命令能启动 `put_rope_ball_in_basket`，并在图形窗口中显示场景。
2. 移动按键可以逐步改变指定手的末端目标位置，另一手保持不动；夹爪按键可开合。
3. 不按键时物理仍推进，且任务动作不连接任何模型服务。
4. 退出后生成多摄像机视频和匹配的 JSONL 控制记录；无风和启风两种运行均能生成有区别的风速标记。
5. 纯 Python 单元测试覆盖按键到控制目标的映射、边界限制、风速解析和轨迹记录序列化；由于本机未安装 Isaac Sim，完整 GUI/PhysX 遥操需要在目标服务器上验收。
