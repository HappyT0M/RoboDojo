# RoboDojo FEM 海绵入碗任务设计

**日期：** 2026-09-29  
**状态：** 等待用户审阅设计  
**目标环境：** RoboDojo 当前使用的 Isaac Sim 5.1.0 / Isaac Lab 2.3.2

## 1. 目标与范围

在 RoboDojo 中新增一个无风操作任务：机械臂抓取一块可通过 FEM 仿真明显压缩、松开后能够回弹的海绵，并将它放进碗里。任务沿用 RoboDojo 的任务注册、场景管理、布局、机械臂、相机和评测接口。

本设计只针对 RoboDojo 及其 Isaac Sim / Isaac Lab 仿真环境。海绵资产、材料设置、对象生命周期、成功判定和验证流程都按 RoboDojo 当前架构与 Isaac FEM 能力设计，不迁移或依赖其他仿真环境的资产、参数或实现方案。

本阶段先完成无风基线。布料和海绵的统一扰动配置及各自受力适配器留到基线验证通过后实施。

## 2. RoboDojo 当前架构情况

- `SceneManager` 目前管理 `rigid`、`dynamic`、`geometry`、`articulation`、`garment` 和 `fluid` 六种场景对象。各类对象分别参与创建、初始化、复位、清理、查找和布局重载。
- `LayoutManager` 也只识别上述六种对象类型。新增 FEM 对象需要扩展布局类型识别、资产路径解析和保存布局加载流程。
- RoboDojo 根据任务模块名动态加载任务类，任务配置使用 YAML；任务评分通过 `run_reward()` 和 `get_score()` 接口执行。
- RoboDojo 目前有刚体碗资产，但 `RoboDojo/Assets` 中没有可直接用于 FEM 仿真的海绵 USD 资产。
- Isaac Lab 2.3.2 提供 `DeformableObject` 和 `DeformableObjectCfg`。具体创建、状态读取和复位方式需要在 Isaac Sim 5.1 的服务器环境中验证。

## 3. 实施设计

### 3.1 先验证 Isaac FEM 海绵资产

在 RoboDojo 项目内准备一个适用于 PhysX FEM 的封闭体积网格，并保存为 RoboDojo 自有 USD 资产。资产应明确区分渲染表面与 FEM 仿真网格，并包含或关联其可形变体 schema、材料和碰撞配置。海绵软硬程度通过 FEM 材料和求解器配置实现，不通过手动改写节点位置伪造形变。

先在 Isaac Sim 5.1 / Isaac Lab 2.3.2 中运行单环境、无机械臂的资产验证场景，再加入夹爪接触。依次验证：

1. 资产能够加载，FEM 节点状态可以读取；
2. 海绵能稳定落在桌面上，不穿透或持续漂移；
3. 夹爪接触时海绵出现清晰可见的压缩；
4. 夹爪松开后海绵能够回弹，且仿真保持稳定。

验证通过后，记录海绵尺寸、质量、网格分辨率、FEM 材料参数、求解器设置和仿真步长。参数以目标 Isaac 环境中的观察和测量为依据。

### 3.2 新增独立的 `deformable` 场景对象类型

新增专用 FEM 对象封装，基于 Isaac Lab 2.3.2 的可形变对象 API，并扩展 RoboDojo 场景管理与布局加载。实现范围包括：

- 注册 `deformable` 类型，并按环境保存对象实例；
- 根据布局创建 FEM 海绵并完成仿真初始化；
- 保存和恢复初始状态，支持场景复位及重载；
- 支持对象查找、删除和清理；
- 为项目自有 FEM USD 资产配置明确的布局格式和路径解析规则；
- 提供读取 FEM 节点位置、速度及必要几何状态的接口，供任务成功判定使用。

该类型独立于刚体、布料和流体对象，不改变现有对象的创建及生命周期。首个里程碑只要求单环境运行；完成单环境创建、复位和评测验证后，再测试多环境并行。

### 3.3 新增无风 `put_sponge_in_bowl` 任务

新增专用任务模块、YAML 配置和初始布局。初始布局包含一块 FEM 海绵和一个 RoboDojo 现有刚体碗；两者放在机械臂可达的桌面区域，并为海绵进入碗口预留足够空间。

任务通过 RoboDojo 现有注册和评测流程加载。语言指令表达“抓起海绵并放入碗中”。机械臂、相机及仿真配置沿用 RoboDojo 当前项目中的设置。本阶段不对已有布料任务作修改，也不启用风力。

### 3.4 基于 FEM 状态判定任务成功

成功判定直接使用海绵 FEM 表面节点或可验证的体积节点状态，不只依赖海绵根节点的位置。将节点坐标转换到碗的局部坐标系，并结合碗口、碗沿和碗内底部的几何范围计算包含关系。

任务成功需同时满足：

1. 海绵主体中心位于碗口水平范围内；
2. 配置比例的海绵表面位于碗沿以下、碗内底部以上；
3. 上述条件连续保持达到配置的稳定时长。

首版将主体中心范围、表面包含比例、碗沿/底部判定范围和稳定时长设为任务配置项。评测时记录实际包含比例、中心位置和稳定计数。阈值在服务器上结合 FEM 节点分布与碗的实际碰撞几何校准，再固定用于评测。

### 3.5 通过无风基线后再接入扰动

本阶段不实现风力。只有海绵通过加载、接触压缩、松开回弹、场景复位和任务评分验证后，再单独设计统一的扰动配置接口，并为布料粒子系统和 FEM 海绵分别实现适配器。

后续风力验证需要对照无风和有风运行结果，检查 FEM 节点速度或位置变化，确认扰动力实际施加到了海绵，而不是只改变了配置或视觉表现。

## 4. 验收条件

- FEM 海绵在 RoboDojo 目标环境 Isaac Sim 5.1.0 / Isaac Lab 2.3.2 中成功加载，且能读取节点状态。
- 单环境仿真中，夹爪接触能使海绵明显压缩，松开后能回弹；仿真没有明显穿透、炸开或持续漂移。
- RoboDojo 能通过常规场景流程创建、查找、复位、重载和清理 FEM 海绵。
- `put_sponge_in_bowl` 能由标准任务注册机制加载，并进入 RoboDojo 现有机械臂、相机和评测流程。
- 成功判定拒绝海绵放在碗旁边或碗沿上的情况，并接受海绵稳定处于碗沿以下的碗内。
- 现有布料任务和风力配置不因新增对象类型而改变。

## 5. 风险与验证边界

- 本地 Windows 环境没有 Isaac Sim，FEM 资产、接触、形变和渲染效果必须在服务器上实测。
- FEM 仿真结果会受到 USD schema、体积网格质量、材料参数、求解器配置和 GPU 环境影响。因此，在写入完整任务前必须先通过独立资产验证。
- 单环境测试通过不代表多环境并行和批量复位已经可靠；这些能力作为后续验证项。
- 成功判定需要使用碗的真实局部坐标和碰撞几何校准，避免仅依赖视觉网格造成误判。
